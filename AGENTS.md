# react-native-template

Opinionated Expo (SDK 57) + TypeScript template. React Navigation (native stack), Reanimated 4, Uniwind (Tailwind CSS v4 on the Unistyles engine), Feature-Sliced Design.

> Expo HAS CHANGED — read the exact versioned docs at https://docs.expo.dev/versions/v57.0.0/ before writing any code.

## Commands

- `npm start` — start the dev server (`npm run ios` / `npm run android` for a platform)
- `npm run lint` / `npm run lint:fix` — ESLint (flat config, `eslint.config.js`)
- `npm run format` — Prettier
- `npm run typecheck` — `tsc --noEmit`

Run `npm run lint` and `npm run typecheck` after making changes.

## Architecture — Feature-Sliced Design

Code lives in `src/`, split into layers (https://feature-sliced.design/):

- `app/` — app initialization: providers, navigation, root `App` component
- `screens/` — the FSD "pages" layer; one slice per screen
- `widgets/` — large self-sufficient UI blocks composed from lower layers
- `features/` — user interactions carrying business value
- `entities/` — business entities (user, product, ...)
- `shared/` — reusable code with no business logic: `shared/ui`, `shared/lib`, `shared/config`

Note: `src/app` is the FSD app layer, NOT an Expo Router directory — this template uses React Navigation with the `index.ts` entry point.

Rules:

- A layer may only import from layers **below** it (app → screens → widgets → features → entities → shared). Never import upward or sideways between slices of the same layer.
- Every slice exposes a public API through its `index.ts`; import slices only through it (e.g. `import { HomeScreen } from '@screens/home'`), never deep paths.
- Use the path aliases from `tsconfig.json`: `@app/*`, `@screens/*`, `@widgets/*`, `@features/*`, `@entities/*`, `@shared/*`.
- Typical slice segments: `ui/`, `model/`, `api/`, `lib/`.

## Styling — Uniwind

- Style with Tailwind classes via the `className` prop on core react-native components (`View`, `Text`, ...) — Uniwind binds it at the Metro level, no wrapper components needed
- Don't use `StyleSheet` (lint-enforced) and don't use inline `style` objects unless a value is truly dynamic (e.g. computed from a gesture/animation)
- When a className combination repeats, extract a component in `shared/ui` (see `Typography` with its variant map); for variant-heavy components use a `Record<Variant, string>` map
- Prefer `Wrapper` naming over `Container`, unless the component holds business logic
- `src/uniwind-types.d.ts` is auto-generated by Metro — never edit it manually (it is committed so `tsc` works on a fresh clone)

## Design tokens

All tokens live in `src/global.css`, in two tiers:

1. **Primitives** (`@theme`) — the raw palette (`--color-neutral-*`, `--color-brand-*`, ...). Tailwind's default palette is wiped with `--color-*: initial`, so primitives are the only raw colors in the system. **Never use primitives in components** (`bg-neutral-100` is technically a valid class — don't).
2. **Semantic tokens** (`@layer theme` → `:root` → `@variant light` / `@variant dark`) — role-based tokens that reference primitives via `var()`. Both variants must define the identical set. These are the only classes components use:
   - `bg-background` (app), `bg-surface` (cards/sheets), `border-border`
   - `text-foreground` (default text), `text-muted` (secondary text)
   - `bg-primary` + `text-primary-foreground` (accent + text on accent)
   - `danger` / `success` / `warning` (feedback)

Rules:

- Never hardcode colors (`bg-[#fff]`, `text-[#111]`) and never use `dark:` color overrides in components — semantic tokens resolve per theme automatically. If a color has no fitting token, add a semantic token (both variants), backed by a primitive
- Name semantic tokens by **role**, not appearance: `--color-muted`, not `--color-light-gray`
- Colored surfaces get a `*-foreground` pair for text/icons placed on them
- Spacing, radii, and font sizes use Tailwind's default scale (`p-4`, `gap-2`, `rounded-md`, `text-base`); customize via `@theme` in `global.css` only when the design calls for it
- Theme switching: `Uniwind.setTheme('light' | 'dark' | 'system')`

## React Compiler

React Compiler is enabled (`experiments.reactCompiler` in `app.json` + `babel-plugin-react-compiler`):

- Don't add manual memoization (`useMemo`, `useCallback`, `React.memo`) — the compiler handles it; write plain components and let it optimize
- Follow the Rules of React strictly (no mutating props/state, pure render) — violations make the compiler silently skip the component; the `react-hooks` lint rules (via `eslint-config-expo`) flag them
- Class components are not optimized — another reason to stick to function components

## Code style

- Prefer arrow functions for components
- Don't use default exports (named exports only; enforced by `import/no-default-export`)
- Prefer `type` over `interface` (exception: `.d.ts` declaration merging)
- Use `import type { ... }` for type-only imports (enforced)
- Import order is enforced by `simple-import-sort` (react → external → FSD layers → relative); run `npm run lint:fix` to sort

- When creating new files, add them to git (`git add`)
